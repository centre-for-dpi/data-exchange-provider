Before creating the service

1What the node publishes

The node reads a view (or a table) from the entity's database and publishes it as a by-key query: GET {service path}/{resource}/{key}.

GET /afiliacion/afiliados/1000000001→ the node validates the key→ SELECT … WHERE numero_documento = ? · read-only→ view salud.v_afiliados→ JSON with the declared columns 
GET /afiliacion/afiliados/1000000001
→ 200 {"numero_documento": "1000000001", "eps": "EPS01", "regimen": "contributivo", ...}

Through the gateway, the consumer calls /<entity>/<api>/v1/afiliados/1000000001. The exact path is on the API's service sheet in the portal.

Four enginesSQL Server, PostgreSQL, MySQL and Oracle. You do not need to install any client on the server: the drivers are built into the node. Tested: Oracle 11g, 21c and 23ai; SQL Server 2019; PostgreSQL 17; MySQL 8.4.
One service, one connectionEach service connects to one database and has one or more resources. Each resource is a view and a key.
Generated OpenAPIThe node generates the contract you upload to the portal, and it already meets the network's rules.
By key onlyThere are no listings, filters, searches or writes.

2Prepare the database (DBA)

The view

The view is the contract

What is not in the view does not go out. Include only the columns that will be shared, with the minimization that the service sheet declares.

  • Simple names: letters, digits and _, starting with a letter or _ (numero_documento, not "Número documento"). Rename a column with any other name in the view with AS.
  • The key column must be text, integer, numeric without decimals, UUID or date. If it is text, it is best if it uses only letters, digits and hyphens (section 6).
  • Unique key, unless the resource is declared with several rows per key (for example, a household with several people).
  • An index on the key column in the source table: each query is a WHERE key = ?.

The read-only user

A dedicated user for the node, with SELECT on the exposed views and nothing else. No broad roles such as db_datareader and no permissions on the source tables: the view is already read with its owner's permissions.

PostgreSQL

CREATE ROLE den_reader LOGIN PASSWORD '<password>';
GRANT CONNECT ON DATABASE entidad TO den_reader;
GRANT USAGE ON SCHEMA salud TO den_reader;
GRANT SELECT ON salud.v_afiliados TO den_reader;

SQL Server

CREATE LOGIN den_reader WITH PASSWORD = '<password>';
USE entidad;
CREATE USER den_reader FOR LOGIN den_reader;
GRANT SELECT ON salud.v_afiliados TO den_reader;

MySQL

the "schema" is the database
CREATE USER 'den_reader'@'<node IP>' IDENTIFIED BY '<password>';
GRANT SELECT ON salud.v_afiliados TO 'den_reader'@'<node IP>';

Oracle

in the PDB; the "database" is the service (e.g. ORCLPDB1)
CREATE USER den_reader IDENTIFIED BY "<password>";
GRANT CREATE SESSION TO den_reader;
GRANT SELECT ON salud.v_afiliados TO den_reader;
  • The password is not written in any configuration file: the installer asks for it without echoing it and stores it in /opt/den-node/secrets/<service>_db_password.
  • doctor checks that the user cannot write to the exposed views. If it can, doctor flags it with ✘.

3Node mode

Instant APIs need the node in completo mode (full: channel plus instant APIs). If it was installed in canal mode (secure channel only), you can switch without losing the node's identity or its services:

sudo /opt/den-node/install.sh mode completoSwitches to the image with the instant APIs and the drivers.
sudo /opt/den-node/install.sh serviceType instant: shows the views the user can read, creates the resource and generates the OpenAPI in /opt/den-node/config/services/<service>.openapi.json.
Configuration

4The service file

Each service lives in /opt/den-node/config/services/<service>.yaml. The installer writes it; you can edit it later (section 8).

name: afiliacion                       # service name: lowercase letters, digits and hyphens
path: /afiliacion                      # "Service path on the node" in the portal
type: instant
title: Afiliación en salud             # optional: OpenAPI title (defaults to the name)
description: Consulta de afiliación    # optional
version: 1.0.0                         # optional: OpenAPI version (defaults to 1.0.0)
database:
  engine: postgres                     # sqlserver | postgres | mysql | oracle
  host: bd.interna.entidad
  port: 5432
  name: entidad                        # the database; on Oracle, the service name
  user: den_reader
  passwordFile: /run/secrets/afiliacion_db_password
  tls: require                         # disable | require | verify
  # caFile: /run/secrets/afiliacion_db_ca.pem   # only with verify (not on Oracle)
  maxConnections: 4                    # concurrent connections to the database (default 4)
  queryTimeout: 5s                     # maximum time per query (default 5 s)
resources:
  - name: afiliados                    # in the URL: /afiliacion/afiliados/{key}
    entity: Afiliado                   # name in the OpenAPI (schema and operationId getAfiliado)
    source: salud.v_afiliados          # schema.view
    description: Afiliado por documento   # optional
    key:
      column: numero_documento         # the column looked up with the key
      # pattern: '[0-9]{6,12}'         # optional: the key's own format
    dataSubject: { documentType: CC }  # if the key identifies a person
    many: false                        # true: the key returns a list
    # maxRows: 100                     # with many: maximum rows (default 100, up to 1000)
    columns:
      - { name: tipo_documento }
      - { name: numero_documento }
      - { name: eps }
      - { name: activo, as: boolean }  # as changes how the column is published (section 5)
Resource fieldWhat it is
nameThe resource name in the URL. Lowercase letters, digits and hyphens, at most 80 characters
entityThe name in the OpenAPI. Starts with an uppercase letter, only letters and digits, unique within the service (Problem is reserved)
sourceThe view or table, as schema.object. Case does not matter
key.columnThe key column. It must be in the view
columnsThe columns that are published. A column that is not listed here does not go out, even if it is in the view
dataSubject personal dataDeclares that the key identifies a person, and with which document type. The portal requires it in personal or sensitive APIs. Without it, the OpenAPI declares that the resource has no data subject
many optionaltrue if one key returns several rows. The response is a list
All or nothing

The whole file is validated before it is applied. If anything does not match the database (a view that does not exist, a misspelled column, an as that cannot be applied), the node serves no resource of the service, and validate and doctor say why.

Only conversions that lose no information are accepted.

6The key

The key arrives in the URL and is validated before the database is queried. An invalid format returns 400 without touching the database.

Key column typeFormat accepted by default
TextLetters, digits and hyphens, up to the column's length. No spaces, quotes or separators
Integer or numberUp to 38 digits. A key that does not fit in the column returns 404 without querying the database
UUIDxxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
DateYYYY-MM-DD

If the entity's keys have another format (for example, with dots or with letters at the end), declare key.pattern with a regular expression. The node anchors it to the whole key. No key can exceed 256 bytes.

7How the API responds

ResponseWhen
200 objectThe key exists (resource without many)
200 listThe key exists (resource with many). The list is sorted by its columns, always in the same order
404 not_foundThe key does not exist, or the resource does not exist
400 invalid_keyThe key does not have the resource's format
400 query_not_allowedThe URL has parameters (?...). Keys always go in the path
405 method_not_allowedA method other than GET
500 non_unique_keyA key declared unique returned two rows. Check the view, or declare many: true
500 too_many_rowsA list exceeded maxRows. It is never silently truncated
500 response_too_largeThe response exceeded 8 MiB
500 unrepresentable_valueA database value does not fit the type the OpenAPI declares (for example NaN, Infinity or a 0000-00-00 date). The log says which column, never the value. Fix it in the view, for example with NULLIF
503 service_unavailableThe database does not respond, or the service file does not match the database (a column changed, or the user has no SELECT on the view)
  • Errors are returned as application/problem+json, with a title in Spanish and a stable code.
  • GET {service path}/ responds {"status":"ok"}, or 503 if the database does not respond: the portal uses it to know whether the service is healthy.
  • If the database goes down, the service responds 503 and the portal shows it as having problems. When the database comes back, the service recovers on its own, without restarting the node.
Operation

8Changing a service

The node's commands run inside the container, from /opt/den-node. Inside the container, the configuration is in /etc/den-node/services/.

cd /opt/den-node
sudo docker compose exec den-node /den-node <command>
CommandPurpose
catalog --service-file /etc/den-node/services/<service>.yamlThe views and tables the user can read, with their columns and whether they can be published
scaffold --print --service-file ... --source schema.view --key column [--resource name] [--entity Name] [--subject CC] [--many]Prints the service file with a new resource that includes every column that can be published
validateValidates all services against their databases
openapi <service>Prints the OpenAPI that you upload to the portal

Removing or adjusting columns

Edit config/services/<service>.yaml: remove the column from columns, or add as to it.

Adding a resource to an existing service

Another view on the same database:

sudo /opt/den-node/install.sh service resource afiliacion

It shows the views the user can read, asks for the view and its key, adds the resource, validates, regenerates the OpenAPI and restarts the node. If anything fails, it leaves the service as it was. The OpenAPI changes, so you must publish a new version in the portal.

After any change

  1. Validate, regenerate the OpenAPI and restart: 
    cd /opt/den-node
sudo docker compose exec den-node /den-node validate
sudo docker compose exec den-node /den-node openapi afiliacion | sudo tee config/services/afiliacion.openapi.json >/dev/null
sudo docker compose restart den-node
  2. If the OpenAPI changed, publish a new version in the portal. The node sends the fingerprint of the OpenAPI it serves in every heartbeat, so the portal knows which contract is behind it. An incompatible change (removing a column, changing its type, changing the key) requires a new major version.
If the view changes in the database

The service keeps serving the declared columns. A new column in the view is not published until it is added to columns. If a declared column is removed from the view, the service stops serving and doctor says which one is missing.

9Security and privacy

Read-only in three layersThe database user, which doctor verifies; a read-only transaction on every query (PostgreSQL, MySQL and Oracle; SQL Server does not have one); and a SELECT generated by the node with the key as its only parameter. View and column names come from the catalog, never from the request.
No content in the logsThe resource, the path template and the result; never the key or the values. Database errors are logged by class, not with the driver's message.
Data is not copiedEach query is answered on the spot from the entity's database, and the node stores nothing.
The database is protectedThe node limits connections (maxConnections), the time per query (queryTimeout) and concurrent requests.

11Limits of this version

  • Only GET by key. There are no listings, filters or searches by body (POST).
  • A new resource in an existing service is added by editing the file (section 8): the installer only creates new services.
  • Oracle was tested with version 23ai. With older versions, it is tested with each entity.
  • On PostgreSQL, timestamp with time zone columns go out in UTC.
